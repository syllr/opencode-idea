这张表由 `idea-run-config-manager` 维护:配置被**新建 / 删除 / 修改**时,对应的行要跟着**加 / 删 / 改**。
配置本身可以由 AI 直接增删改 —— 照 `assets/types/` 里那个类型的模板写 `.run/<配置名>.run.xml`;**没有模板的类型交给用户在 IDE 里配**。
**服务化的配置不在本表** —— 它们已经登记在 `AGENTS.md` 的 `idea-standalone` 块里;本表收的是**其余**的 run configuration。

## run configuration 一览

<!-- 生成提示:begin -->

**先过滤**:动手前读 `<项目根>/AGENTS.md` 里 `idea-standalone` 的标记块,把它的表里出现过的 run configuration 名字收集起来 —— **这些一律不进本表**(它们服务化 / 长驻,端口与热重载已在那边写清)。剩下的才是本表内容;没有那个块就不过滤。
**枚举以工具为准**:各项目各有自己的工具前缀(root 是 `ide`,子项目是它的目录名),看哪个项目就用**它自己那个前缀**的工具 —— `<前缀>_get_run_configurations` 直接调用,不传参数,它给出 IDE 真正认的配置(含存在 `.idea/` 里的那些,单翻 `.run/` 目录看不到)。**项目与各子项目里真正存在的、过滤后剩下的都要有。**
**项目**列写那套工具的前缀(root 写 `ide`,子项目写它的目录名):一条配置属于谁、该用哪套工具去看和跑,由这一列决定。
`run configuration` 列必须是该前缀下**真实存在的名字**,不凭印象写;表里有、项目里已经没有的**整行删掉**。
**按操作系统分成两张表**:macOS / Linux 一张,Windows 一张。同一份流程在两个平台上常常不是同一条命令(解释器不同、脚本后缀不同、路径写法不同),所以**按这个配置真正能跑的那个平台归表**,不要把 Windows 上才成立的命令写进 macOS 那张表。判断依据看配置里的解释器路径与脚本内容(例如 `INTERPRETER_PATH` 指向 PowerShell、命令里有 `\` 路径的,就是 Windows);**判断不了就问用户**,不猜。只在一个平台成立的流程就只写那一张表。

**怎么跑**写走哪条工具:跑完即退的用 `<前缀>_execute_run_configuration`;长驻进程用 `<前缀>_rerun_run_configuration`(在跑就重启、没在跑就启动)。**不要**用 `execute` 跑长驻进程 —— 它是 Run 路径,对常驻进程**它会起出重复实例**。
**何时跑**写触发场景(改完表结构 / 发版前 / 换分支后 / 只在联调时 …)。
**跑前做**写**跑之前要先做的事**(先装依赖 / 先构建 / 先起某个服务):**多数留空**。确实得先做点什么才写,而且**按顺序写清第 1 步、第 2 步**。前置事项往往**不是**一个 run configuration(没有对应配置),所以只能写在这里 —— 漏了它,照着表跑的人会直接跑出一个起不来的流程。
**说明**是这个配置唯一的自由文本格:**它是什么、干什么的**(同步某个环境的 DDL / 生成代码 / 跑迁移 …),以及有什么坑(必须先备份 / 只对某个环境生效 / 幂等与否 …)。
分两件事都往这里写,**不要再单开一列**。写清它到底跑什么命令,就读它所在项目的落地文件 `.run/<name>.run.xml` 看里面的内容,拿不准就**问用户**,不猜。
这张表的**主要价值**就在这一格:下次要办同类事情先在这里搜关键词,找得到就直接用,**不要再建一个重复的**。
**目录、端口这类"配置里本来就有"的字段不要抄进来** —— 它们会跟配置变旧而对不上;确实要交代依赖关系,就写进 `说明` 或 `跑前做`。
**列宽按同一约定**(中文两字 = 四个 dash,英文按字符数),**与 `idea-standalone` 的两张应用表公共列一一对位、宽度一致**(谁 / `run configuration` / `怎么跑` / `何时跑` / `跑前做` / `说明`);**各自的特有列插在自己的语义位置上** —— 那边的应用表多一格 `端口`(服务化应用一定有),本表没有,固定流程不是服务。**某格不适用就留空,不要写 `-`;填行时别去改表头的空格。**
