### 一、什么是 standalone 模式

<!-- 生成提示:begin -->

**standalone = 通过 IDEA 启动** —— 应用在本机进程直跑,不容器化、不部署到远端。给"本项目在本机的运行形态"下定义,至少覆盖:

- **通过 IDEA 启动**:每个应用的启动入口就是 IDEA 的 run configuration(Run / Debug),不是手搓命令行。
- **应用在本机进程直跑**:不容器化、不部署到远端;本机**不跑**什么也要写明(例如需要 GPU 的服务、或本机直连的远端数据库)。
- **只启动其中一部分是常态** —— 不要求所有应用都起来,用户可能只开一两个。
- **启停只走这三个工具**:启动 / 重启用 `idea_rerun_run_configuration`(在跑就重启、没在跑就启动),停止用 `idea_stop_run_configuration`,
  查状态用 `idea_list_running_configurations`。**跑应用只能用 `idea_rerun_run_configuration`**。
- **不要用 `idea_execute_run_configuration` 启停这些应用**:它是给**命令 / Job 类型**的配置跑的,standalone 的应用是常驻进程,
  用它只会起出重复实例。
- **也不要绕过 IDEA**:不用 `go run` / `pnpm dev` / `uvicorn` / `python -m ...` 这类裸命令起进程,更不要 `kill` / `pkill` 业务进程 ——
  外部杀掉的进程 IDE 并不知道(Run 窗口仍显示运行中,下次启动就撞端口)。
- **重启不必先问**:改完代码要重启哪个应用,直接 `idea_rerun_run_configuration` —— 这条链是无人化的,先征求同意只会把重启卡住。
- 工具列表里没有上面那三个工具时(没装配套插件):启停交回用户,请他在 IDEA 里手动做,AI 不动手。
- **与部署链纪律互不构成许可**:本段管的是**本机 standalone 的启停方式**,不适用于部署流程;反过来,部署链里的步骤也不构成"可以绕开本段、用裸命令在本机起应用"的许可 —— 两阶段纪律互相独立。

### 二、standalone 下启动哪些应用(必须经 IDEA run configuration)

<!-- 生成提示:begin -->

一行一个应用。`run configuration` 列**必须是 `idea_get_run_configurations` 里真实存在的名字**,不凭印象写;缺配置就**交给用户**:
请他在 IDEA 里自己建一个,不要手搓启动命令,也不要自己写 `.run/*.run.xml`。端口写清"固定 / 默认 / 被占用即启动失败",读不到就**问用户**,不要编。
**哪个应用必须先起来**也要写明(例如前端 dev server 的 proxy 指向本机后端)。与本项目无关的应用不写。

### 三、热重载矩阵:改代码后要不要提醒重启

<!-- 生成提示:begin -->

逐应用判定。热重载列必须有依据(运行方式 → 有没有 HMR),不确定就问用户,不猜。非热重载的应用改动后,**不得**在没有提示的情况下宣称
"改动完成 / 可以去验证了";重启动作由用户手动做。`go run .` 这类**没有热重载**的写法要写进来,别让 AI 以为改了代码就自动生效。
