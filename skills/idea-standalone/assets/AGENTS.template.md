## 一、什么是 standalone 模式

**standalone = 启动收口只有 IDEA run configuration** —— 每个应用的启动入口是 IDEA 的 run configuration (Run / Debug)
,不是手搓命令行;至于配置内部怎么起 (**本机进程 / 容器 / 部署到远端**)
,由它自己决定,本段不预设。给"本项目怎么起、起在哪"下定义,至少覆盖:

- **入口唯一 (唯一绝对的约束)**:每个应用的启动入口就是 IDEA 的 run configuration, **不是手搓命令行**。
- **形态不限**:配置可以起本机进程,也可以是容器 (Compose / K8s)、或部署到远端 —— 怎么起是配置的事,
  **不要假设它一定在本机直跑**。相应地,哪些应用 **不在本机跑、或本机起不来**要单独写明 (需要 GPU
  的服务、本机直连的远端数据库、只能部署后验证的服务),别当成"本机直跑"来验证。
- **只启动其中一部分是常态** —— 不要求所有应用都起来,用户可能只开一两个。
- **跑应用只用 `<前缀>_rerun_run_configuration`**:在跑就重启、没在跑就启动 —— 不必分辨"这是启动还是重启",直接 rerun 就完事。
  常驻进程化 / 服务化的 run configuration 一律走这一条。
- **不要用 `<前缀>_execute_run_configuration` 跑这些应用**:它是给 **命令 / Job 类型**的配置跑的,standalone 的配置是
  **常驻型**(起来就不退),
  用它只会起出重复实例。
- **也不要绕过 IDEA**:不用 `go run` / `pnpm dev` / `uvicorn` / `python -m ...` 这类裸命令起进程,更不要 `kill` / `pkill`
  业务进程 ——
  外部杀掉的进程 IDE 并不知道 (Run 窗口仍显示运行中,下次启动就撞端口)。
- **重启不必先问**:改完代码要重启哪个应用,直接 `<前缀>_rerun_run_configuration` —— 这条链是无人化的,先征求同意只会把重启卡住。
- 工具列表里没有 `<前缀>_rerun_run_configuration` 时 (没装配套插件):交回用户,请他在 IDEA 里手动跑,AI 不动手。
- **与部署链纪律互不构成许可**:本段管的是 **standalone 跑应用的方式**
  ,不适用于部署流程;反过来,部署链里的步骤也不构成"可以绕开本段、用裸命令在本机起应用"的许可 —— 两阶段纪律互相独立。

## 二、standalone 下启动哪些应用 (必须经 IDEA run configuration)

<!-- 生成提示:begin -->

一行一个应用。 **`run configuration` 列填 base 名**(不带任何 `@` 段)—— 平台与环境由名字里的段决定,见上面「run
configuration 名字怎么读」。 **变体不另起行**:`win@base`(换平台)、`base@env`(换环境)都是同一个 base
的变种,写一行就够,怎么选走「选哪个变种」那节。

`run configuration` 列 **必须是 `<前缀>_get_run_configurations` 里真实存在的 base 名**,不凭印象写;缺配置就 **交给用户**:
让他调 `idea-run-config-manager` skill 去建 (那个 skill 管这个项目 run configuration 的增 / 删 / 改),不要手搓启动命令,也不要自己写
`.run/*.run.xml`。 **before run** 写 **跑之前要先做的事**:**多数应用写 `无`**(这一格始终填,不留空)
。只有确实"得先做点什么才能起"时才写,而且 **按顺序写清第 1 步、第 2 步、第 3 步**(例如 `1. 装依赖 2. 构建 3. 起前置服务`);
这些事 **用文字写出来**(AI 照这段文本自己按序去做)。这类前置事项往往没被写成 run configuration,所以必须在这里说明,否则 AI
直接 rerun 会拿到一个起不来的进程。 **哪个应用必须先起来**也要写明 (例如前端 dev server 的 proxy 指向本机后端)
。与本项目无关的应用不写。 **run** 写走哪条工具:常驻 / 服务化的配置一律 `rerun`(在跑就重启、没在跑就启动), **不要**用
`execute` —— 它是 Run 路径,对常驻进程会起出重复实例;细节见「跑应用只用 rerun」那条。 **port** 写清"固定 / 默认 /
被占用即启动失败";读不到就 **问用户**,不要编。 **服务化的应用一定有端口**,这一格是它区别于固定流程的地方。 **after run** 写
**起来之后才知道的结果**:日志落在哪 / 什么时候才算 ready / 起来之后要接着做什么 (要跑迁移、要把地址交给谁); **多数写
`无`**。 **desc** 写剩下的坑与依赖关系 (依赖谁、跟别的应用什么先后),以及例外 (**只在联调 / 某个流程之前才需要起**之类)。
**目录**这类配置里本来就有的字段不要单开一格 —— 会跟配置变旧而对不上。 **有 `@` 变体就在这里补一句**:有哪些变体、各自怎么切环境
(如 `console-web@yutao` 靠 `APP_ENV=yutao` 环境变量)。 **列宽按同一约定**(英文按字符数), **表头与
`idea-run-config-manager` 那一块的列一一对位、宽度一致**。 **列名与 `idea-run-config-manager` 的条目项同名同序**
(`before run` / `run` / `after run` / `desc` 四项); **本表多 `app` / `run configuration` / `port`**
(服务化应用一定有端口), **少一项 `when`** —— 服务化应用就是"改完代码要起它来测"的时候起,没有别的时机可写。两个块住在同一份
`AGENTS.md` 里,名字与顺序对上了才看得出哪些是服务、哪些是固定流程。 **本块保持表格形式**(那边是条目式:
应用有端口这样的短列,表格更好扫)。 **某格确实没有内容就写 `无`**(不省略、也不写 `-`);填行时别去改表头的空格。

### run configuration 名字怎么读

<!-- 生成提示:begin -->

本节是 **固定文本**,照抄,不要改写、不要删条目 —— 它是读名字的规则,下面那张表靠它才成立。
<!-- 生成提示:end -->

run configuration 的名字是 `[os@]base[@env]`,`@` 分割、最多三段:

| 段   | 位置 | 取值     | 缺省表示           |
| ---- | ---- | -------- | ------------------ |
| os   | 最前 | `win`    | macOS / Linux      |
| base | 中间 | 配置本体 | 必填               |
| env  | 最后 | 环境名   | 所有环境通用这一套 |

`win@base`(换平台)与 `base@env`(换环境)都是 `base` 的 **变种**:同一个应用、同一件事,只是平台 / 环境不同。 **表里只登记
base**,变种不另起一行、不逐个列 —— 变种怎么选见下面「选哪个变种」。

### 选哪个变种 (启动前必须做对)

<!-- 生成提示:begin -->

本节是 **固定文本**,照抄,不要改写。
<!-- 生成提示:end -->

1. **先落到具体名字**:macOS/Linux 用 `base`;Windows 用 `win@base` —— `win@base` 不在 `get_run_configurations` 里,说明这个应用没有
   Windows 侧的配置, **交回用户**,别拿 base 顶替。
2. **再定环境**:有 `base@<env>` 变体时,`<env>` 就是环境名。`base` 与 `base@<env>` 同时存在 = 同一件事的两套环境 →
   **启动前问一次用户走哪套**(问"走哪个环境",不是"要不要启动")。
3. **问一次就够**:用户选定后, **本会话内默认走这一套**,用户不说改就不改;只有当你判断环境要变 (用户提到换机器 /
   换环境、要部署到别处)才再确认一次。
4. **确认过就别再打扰**:改代码 → 自己重启 → 同一套变体 —— 这正是 standalone 要达到的:AI 干活的链路上不打扰用户。
5. **环境怎么切是代码的事**:每种语言 / 框架各有各的做法 —— 有的靠环境变量 (`APP_ENV=yutao` 之类),有的靠启动参数
   (`--env-file=env/yutao.env` 之类)。 **读代码确认这一套怎么切**,别猜;实在看不出来就问用户。

## 三、热重载矩阵:改代码后要不要提醒重启

<!-- 生成提示:begin -->

逐应用判定。热重载列必须有依据 (运行方式 → 有没有 HMR),不确定就问用户,不猜。非热重载的应用改动后, **不得**在没有提示的情况下宣称
"改动完成 / 可以去验证了";重启动作由用户手动做。`go run .` 这类 **没有热重载**的写法要写进来,别让 AI 以为改了代码就自动生效。
